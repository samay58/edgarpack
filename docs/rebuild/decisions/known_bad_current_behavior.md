# Known-Bad / Suspicious Current Behavior (Phase 0 capture)

Purpose: inventory current behaviors that may be wrong, brittle, or undesirable, but that a clean-room rewrite must still CAPTURE (and consciously decide on) before changing them. This is a behavior-pinning artifact, not a fix list. Each row carries evidence (`file:line`), why it may be wrong, why it may still need pinning, a proposed future treatment, and confidence.

Source basis: the `known_bad`/`edge_cases` arrays of the 15-slice discovery corpus, `docs/BACKLOG.md` (the 2026-06-09 whole-project adversarial review, file:line-cited), and direct code/test re-confirmation of the load-bearing citations. The memory-noted query bugs (per-share LTM, annual-only LTM-1 stubs, Q4 early-return, strict recursion, fail-closed ltm-N, HK column-shift) are included only where current code/test evidence supports them; all of those are now CLOSED with regression tests, so they appear as "preserve" (do not regress), not as open defects.

Treatment legend: `preserve` = keep exactly as-is (parity corpus pins the current output); `fix` = the review/evidence already says this is a real defect to correct in vNext; `uncertain` = needs Samay's call on whether to pin the current output or the intended output; `deprecate` = candidate for removal pending a caller check.

## Notes and caveats

- **The biggest deferred batch is parse-pipeline (BACKLOG.md items 1-6, 10).** Sectionizer TOC bugs (`parse/sectionize.py:572-590`, `557-559`), page-break artifacts in section markdown (`md_polish` `_TOC_HEADING_RE` ordering), tokenizer-fallback nondeterminism (#5), and the SSE TOC guard (`sse/sectionize_cn.py:77-80`) are explicitly grouped in the review as "one PARSER_VERSION bump + fixture regen, do together." Any of these changes section ids, which ripples into diff section matching and any test asserting canonical ids. Capture the current (buggy) section behavior in the parity corpus before the bump.

- **Determinism has no offline regression test.** `tests/test_determinism.py` is gated on `--run-slow` AND `--run-live-sec` and runs only against NVDA's 10-K (`0001045810`). The tokenizer fallback (#5), the SSE+translate manifest mutation (#37), the latin-1 fallback (#32), and the distill path-leak (#16) can all break byte-identity in environments the fast suite never exercises. The rewrite should add an offline, fixture-driven determinism test.

- **Closed bugs are pinned by tests, so do not "rediscover" them.** Items 17-24 are corrected in current code with regression tests (`tests/test_periods.py`, `tests/test_self_heal.py`, `tests/eval/china_golden.yaml`). The corpus and BACKLOG.md:24-26 confirm the 2026-06-09 fix run closed the per-share LTM, annual-only LTM-1, Q4 early-return, strict-recursion, exact-prior-FY, fail-closed ltm-N/mrq-N, mrp-offset, inert-self-heal, and HK column-shift items. Treat them as parity behavior to reproduce, not defects to re-fix.

- **The HKEX/SSE `known_bad` items (#1-4, #9, #24, #35-37) are the densest correctness cluster** and several touch the cited-value promise directly. The China Lens golden harness (`tests/test_china_query_eval.py` against `china_golden.yaml`) already pins the regex-path numbers within tolerance and carries known failures as strict xfail (bead `edgarpack-483`: HK multi-line-label extraction suppressing `operating_cash_flow` and `r_and_d` at the query layer even though the values are present in `facts.json`). That xfail is itself a captured known-bad worth preserving as a strict-xfail in the rewrite's harness.

- **One docs-vs-docs discrepancy to resolve before trusting either as the oracle:** the 2026-04-27 XGIMI research note records bare 6-digit A-share code `688696` being treated as SEC CIK `0000688696` -> 404 -> `Revenue: N/A`, while `docs/china-lens/IMPLEMENTATION_TRACKER.md` claims raw A-share codes now route correctly. The note predates the generalized-company-resolver work; code is the arbiter, but Phase 0 does not run it. Flagged as uncertain.

- **Confidence calibration:** `high` = re-confirmed against current code/test this pass or directly file:line-cited in BACKLOG.md as repro-verified; `medium` = single corpus/BACKLOG signal, plausible but not re-run; `low` = inferred from one weak signal (e.g., a refactor-residue or read-compat path). Where the corpus marked an item `uncertain`, this document preserves that rather than upgrading it.
