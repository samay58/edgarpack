# EdgarPack Docs Map

Use this file as the first stop when you know the kind of answer you need but
not the exact document name. The root `README.md` remains the product entry
point; this directory is the deeper reference surface.

## User Guides

- `GETTING_STARTED.md`: first install, first query, first pack, first diff.
- `WORKFLOWS.md`: task-oriented research recipes.
- `S1.md`: how to build and query S-1 packs.
- `QUERY.md`: metric, period, derived-value, JSON, and citation reference.
- `OBSERVATORY.md`: filing diffs, HTML reports, and registration timelines.
- `BENCHMARKS.md`: compression and token-count methodology.
- `METRIC_DIRECTORY.md` and `METRIC_DIRECTORY.json`: generated metric catalog.

## Code And Agent Orientation

- `../ARCHITECTURE.md`: high-level code map and pipeline stages.
- `learn/`: narrative code walkthroughs and module references generated by
  `.learn-pack`.
- `TESTING.md`: local, live, China, web, and release validation lanes.
- `SYMPHONY.md`: Linear/Symphony operating runbook for agent work.
- `superpowers/`: saved specs and plans from structured design sessions.

## Product Areas

- `china-lens/`: China Lens implementation state and commands.
- `OBSERVATORY-EXPLAINER.md`: product framing for the filing observatory.
- `research/`: small research notes that support product or implementation
  decisions.

## Archives And Assets

- `archive/`: historical plans and prompts that are useful context but not the
  current roadmap.
- `assets/`: committed images used by docs and the root README.

## Placement Rules

- Put durable user-facing docs at `docs/<TOPIC>.md`.
- Put internals walkthrough material under `docs/learn/`.
- Put implementation plans/specs under `docs/superpowers/`.
- Put small decision-support notes under `docs/research/`.
- Put historical or superseded material under `docs/archive/`.
- Do not put generated pack/site/report outputs in `docs/`; use `packs/`,
  `site/`, or `reports/` instead.
