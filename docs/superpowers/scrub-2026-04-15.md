## Critical (correctness bugs or broken docs)

1. HKEX pack query is hardcoded to FY 2024 and cannot resolve other pack years
- File/line: `edgarpack/query/financials.py:937`
- Old text:
```python
    fy = 2024
```
- Replacement:
```python
    fy = _resolve_pack_fy(resolved, period)
```
- Impact/rationale: pack lookup is locked to `<alias>_2024`, so HKEX fixtures for any non-2024 fiscal year are never discoverable even when present, causing `FileNotFoundError` on valid company-year combinations and making non-2024 datasets unusable.

2. `lfy-N` ignores caller `period_offset`, breaking derived metric composition and multi-year math
- File/line: `edgarpack/query/periods.py:964`
- Old text:
```python
    if lfy_back_match:
        years_back = int(lfy_back_match.group(1))
        return select_lfy(
            facts,
            concept,
            metric,
            meta,
            company,
            cik,
            taxonomy=taxonomy,
            doc_map=doc_map,
            period_offset=-years_back,
        )
```
- Replacement:
```python
    if lfy_back_match:
        years_back = int(lfy_back_match.group(1))
        return select_lfy(
            facts,
            concept,
            metric,
            meta,
            company,
            cik,
            taxonomy=taxonomy,
            doc_map=doc_map,
            period_offset=(period_offset or 0) - years_back,
        )
```
- Impact/rationale: `_compute_derived` already propagates component offsets (`period_offset=comp_offset`) and calls `select_period`, so a composed metric like `revenue_growth_yoy` with nested `lfy-1` components should shift on top of inherited offset; dropping the incoming offset collapses both sides of comparisons to the same year.
- Cross-reference: `edgarpack/query/financials.py:629-680` propagates `comp_offset` into derived component lookup.
