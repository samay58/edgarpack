# Self-heal v2.1 Followups

> Tracking doc for deferred work surfaced during the v2 Layer B build and its reviews.
> Use `bd create` to file individual tickets for the items that warrant it.

## Background

Self-heal v2 Layer B shipped on 2026-04-11 via feat/self-heal-v2-layer-b. During the 13-task implementation and its per-task code reviews, several Important and Suggestion items were deferred to v2.1 because they require broader refactors or cross-layer coordination. This document is the single source of truth for those followups.

## Items

### 1. Structured failure reason from `try_extract_kpi` [Important]

**Context**: `try_extract_kpi` has 9 distinct None-return sites. The orchestrator in `financials.py:215-225` collapses them all into one `Diagnostic(kind="layer_b_unresolved", message="...")`. The v2 `Diagnostic.kind` enum has 5 values, 4 of which are currently unreachable.

**Action**: refactor `try_extract_kpi` to return a structured result. Options in the code review were:
- `tuple[CitedValue | None, FailureReason | None]` with a dedicated enum
- `ContextVar[str]` for last-failure-reason (hidden state, not preferred)

**Effort**: ~1-2 days. Touches kpi_extract.py (9 sites) + financials.py wire-up + tests.

### 2. Pull `period_of_report` into pack manifest [Important]

**Context**: Layer B currently sets `period_end = date.min` as a sentinel because the pack manifest's `filing` block doesn't carry the fiscal period end. `_build_cited_from_extraction` notes this with a TODO(layer-b).

**Action**: extend `harvest/runner.py` or wherever manifest is written to include `period_of_report` from the SEC filing index. Bump manifest schema version. Update `_build_cited_from_extraction` to read it.

**Effort**: ~half day. Mostly harvest-side.

### 3. Lift `verify_order_of_magnitude` to shared utility [Suggestion]

**Context**: `kpi_extract.py` imports `verify_order_of_magnitude` from `self_heal.py` via a lazy import inside `_verify_against_prior_filing` because of the `concepts -> kpi_extract -> self_heal -> concepts` cycle.

**Action**: extract `verify_order_of_magnitude` into `edgarpack/query/_verification.py` (stdlib-only). Both `self_heal.py` and `kpi_extract.py` import it at module top. Cycle disappears.

**Effort**: 15 minutes. One function move + two import updates + no test changes.

### 4. Excerpt persistence in `learned_concepts` [Suggestion]

**Context**: The cache path in `try_extract_kpi` can't populate `excerpt_text` on the rebuilt `CitedValue` because `LearnedRow` doesn't persist the excerpt. Cache hits degrade to concept-label text fragments instead of excerpt-based deep links.

**Action**: schema migration v2 -> v3 adding `excerpt_text TEXT NOT NULL DEFAULT ''` column. Update `LearnedRegistry.upsert/lookup/LearnedRow`. Populate in `try_extract_kpi`.

**Effort**: ~2 hours including migration test.

### 5. Industry metadata on `KPI_CATALOG` entries [Suggestion]

**Context**: `KpiDef.industry: tuple[str, ...]` exists but is unused. All 25 entries have `industry=()`.

**Action**: populate the existing entries with their SIC code prefixes (e.g. `("737",)` for SaaS, `("52",)` for retail). Unlocks `edgarpack learned suggest --industry saas`.

**Effort**: ~30 minutes for the catalog pass.

### 6. `edgarpack learned suggest` command [New feature]

**Context**: Builds on item 5. A CLI command that lists KPIs applicable to a given company based on its SIC classification.

**Action**: new subcommand `edgarpack learned suggest <company> [--industry X]`. Filters `KPI_CATALOG` by `industry` matching the company's SIC.

**Effort**: ~2 hours.

### 7. Catalog curation tooling [New feature]

**Context**: Spec explicitly deferred this. A `scripts/curate_kpi_catalog.py` that walks existing packs, samples KPI-candidate phrases from prose, and suggests new catalog entries.

**Action**: standalone script using the existing pack infrastructure.

**Effort**: ~1 day.

### 8. `edgarpack learned promote` PR diff generator [New feature]

**Context**: Spec explicitly deferred. A command that takes frequently-hit learned rows and emits a PR-ready diff promoting them into `METRIC_MAP` (for Layer A) or `KPI_CATALOG` (for Layer B).

**Action**: new subcommand + diff formatter.

**Effort**: ~1 day.
